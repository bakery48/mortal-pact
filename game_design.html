コンセプト

「育てた魔物はいつか老いる。だからこそ、命をつなげ。」

プレイヤーは魔物使いとなり、カードから魔物を召喚して戦うデッキ構築ローグライト。 魔物には一生（ライフサイクル）があり、使い込むほど強くなるが、やがて老いて消滅する。 2体の魔物を合体させることで子孫カードを生み出し、親の特性を引き継がせることができる。

差別化ポイント

既存のデッキ構築ゲーム（Slay the Spire等）との差別点：

カードに「一生」がある

静的なカードではなく、使うたびに変化・成長・老化する。

タイミングの戦略性

「いつ合体させるか」「いつ使い捨てるか」の判断が生まれる。

子孫による継承

親の特性を引き継ぐ子孫カードが生まれ、ラン間をまたいだ育成感がある。

感情移入

育てた魔物が老いて消えていく喪失感と、子孫への継承という物語性。

魔物のライフサイクル

幼体（弱い）→ 成体（強い・ピーク）→ 老体（弱体化）→ 消滅
                    ↑
              ここで合体すると
              子孫カードが生まれる（推奨タイミング）

成長段階の詳細

段階状態戦闘力備考
幼体🥚 生まれたて低コスト安め
若体🌱 成長中中使うほど成長
成体⚔️ ピーク最大合体推奨タイミング
老体🍂 衰退低下コスト増・効果減
消滅💀 死使用不可デッキから除外

成長の仕組み

  • 魔物カードを使用するたびに経験値（EXP）が蓄積
  • EXPが閾値を超えると段階が上昇
  • ピーク（成体）を過ぎると自動的に老化が始まる
  • 老体になると毎ターン使用コストが上昇し、効果が低下

合体システム（子孫生成）

合体の方法

  • 手札の成体（または老体）の魔物カード2枚を選択して合体コマンドを実行
  • 両親のカードはデッキから消滅
  • 子孫カード1枚が新たにデッキに加わる

子孫への継承

親A（炎属性・攻撃特化）
  ×                   →  子孫（炎+氷の複合属性・攻守バランス型）
親B（氷属性・防御特化）
  • 属性：親どちらかまたは混合
  • コマンド：両親のコマンドからランダムで引き継ぐ
  • 成長速度：両親の平均値
  • レアリティ：確率で親より上のレアリティになる場合がある

戦闘システム

ターン構造

【プレイヤーターン】
1. エネルギーが3回復
2. 手札からカード（魔物）を選択
3. その魔物のコマンドを選択して実行
4. エネルギーが続く限り繰り返し可能
5. ターン終了を宣言

【敵ターン】
6. 敵が行動（事前にアイコンで予告される）

【ターン終了処理】
7. 状態異常・バフ・デバフを更新

カード（魔物）の構成

┌─────────────────────┐ │ 🐺 フェンリル │ │ [成体] EXP ████░ │ │ ATK:12 DEF:6 │ │ │ │ ▶ 噛みつき コスト1 │ │ 物理12ダメージ │ │ │ │ ▶ 遠吠え コスト2 │ │ 味方全体ATK+2(1T) │ │ │ │ ▶ 狂化 コスト3 │ │ 次のコマンドが2倍 │ └─────────────────────┘

エネルギーシステム

  • 毎ターンエネルギー3から開始
  • コマンドにはコスト1〜3がある
  • エネルギーは翌ターンに持ち越せない

属性相性

属性は 6種（＋無属性）。攻撃属性と相手の属性の相性で与ダメージが増減する。

4すくみ（有利で ×1.5 / 不利で ×0.75）

水 ＞ 炎 ＞ 風 ＞ 土 ＞ 水 …（一周）
  • 水は炎に強い／炎は風に強い／風は土に強い／土は水に強い
  • 有利な側の与ダメージは ×1.5、不利な側は ×0.75

光 ⇔ 闇（相互弱点）

  • 光と闇は互いに弱点。どちらから攻撃しても ×1.5

仕様メモ

  • 無属性は相性の影響を受けない（常に ×1.0）
  • 複合属性の子孫は、いずれかが有利なら有利、無ければ不利を採用
  • カードのダメージ表記に ▲有利 / ▽不利 を表示、敵パネルに敵の属性を表示
  • 相性が乗るのは直接ダメージ（通常・貫通）。毒など固定ダメージには乗らない

デッキ構成

  • 初期デッキ：魔物カード5枚
  • デッキ上限：15枚（拡張可能）
  • 1バトルで手札に引けるカード数：5枚（使ったカードは山札の一番下へ）

MVP（最初に作る最小構成）フェーズ1〜5 実装済み

Steamリリースに向けた最初のマイルストーン：

フェーズ1：コア戦闘

  • 戦闘画面の実装
  • カード（魔物）の召喚・コマンド選択
  • エネルギーシステム
  • 敵のHP・行動予告・攻撃

フェーズ2：ライフサイクル

  • 魔物の成長段階（幼体〜消滅）
  • EXP蓄積と段階移行
  • 老体の弱体化処理

フェーズ3：合体

  • 合体コマンドの実装
  • 子孫カード生成ロジック（属性・コマンド継承）

フェーズ4：ラン構造

  • マップ（バトル→ショップ→ボス）
  • 報酬（新しい魔物カードの獲得）
  • ゲームオーバー・クリア処理

フェーズ5：コンテンツ拡充

  • 魔物の種類を増やす（カタログ46種・コマンド効果12種でロール分化）
  • 状態異常システム（毒・炎上・凍結・再生）
  • 敵の種類を増やす
  • ボスの実装
  • BGM・SE

追加：セーブ・ロード

  • ラン状態を JSON でユーザーディレクトリに保存・自動再開

技術メモ（Godot 4.x）

推奨シーン構成

res://
├── scenes/
│   ├── battle/
│   │   ├── battle.tscn         # メイン戦闘シーン
│   │   ├── card.tscn           # カードUI
│   │   └── enemy.tscn          # 敵
│   ├── map/
│   │   └── map.tscn            # ランマップ
│   └── ui/
│       └── hud.tscn            # HUD
├── scripts/
│   ├── card.gd                 # カードデータ・ライフサイクル
│   ├── player.gd               # プレイヤー状態管理
│   ├── enemy.gd                # 敵AI
│   ├── battle_manager.gd       # 戦闘進行管理
│   └── deck_manager.gd         # デッキ操作
├── resources/
│   └── monsters/               # 魔物データ（Resourceファイル）
└── assets/
    ├── sprites/
    └── audio/

データ管理方針

  • 魔物データは Resource クラスを継承したカスタムリソースで管理
  • ライフサイクルの状態は各カードインスタンスが保持
  • セーブデータは JSON 形式でユーザーディレクトリに保存
